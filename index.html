CF Workers Design System

A design-system site that is intentionally easier for agents to consume than a typical docs website. Humans get a clear index. Agents get stable entrypoints, plain files, short aliases, machine-readable discovery, and first-class Markdown delivery.

Primary: /manifest.json Fast index: /agent-index.json Plain guidance: /llms.txt Markdown index: /site.md Raw docs: *.md Negotiated markdown at /

Why This Is Better For Agents

  • One canonical discovery file: /manifest.json.
  • Short predictable URLs for the most important assets.
  • Everything important is plain .json, .md, or .css.
  • No client-side app shell or JavaScript-rendered navigation is required to find the data.
  • The design skill is published as a first-class artifact, not buried in prose.
  • A tiny /agent-index.json gives fast, low-token retrieval for common tasks.
  • CORS-friendly static delivery makes direct tool fetching straightforward.

Choose Files By Task

  • Landing page: /tokens.json, /components.md, /product-pages.md
  • Calculator/tool: /tokens.json, /components.md, /prompting.md
  • Agent setup: /skill.md, /agent-index.json, /llms.txt
  • Task routing: /examples.json, /agent-index.json, /manifest.json
  • Raw token ingestion: /tokens.json or /tokens.css

The goal is to reduce broad crawling. An agent should fetch the minimum number of files needed for the current UI task.

Recommended Agent Flow

  1. Fetch /manifest.json.
  2. Read /skills/cf-workers-design/SKILL.md or /skill.md.
  3. Load /tokens/tokens.json for machine-friendly values.
  4. Load only the docs or references needed for the current task.

DESIGN.md

/design.md publishes the complete design system in the design.md open format — a single file combining machine-readable YAML token frontmatter with human-readable brand rationale. Use it with any tool or agent that supports the format natively, or read it directly as structured documentation.

The YAML frontmatter covers colors, typography, rounded corners, spacing, and component tokens. The markdown body follows the spec section order: Overview → Colors → Typography → Layout → Elevation & Depth → Shapes → Components → Do's and Don'ts.

Agent-First Vs. Website-First

Typical docs site This site
Start from a homepage and click around. Start from /manifest.json and fetch only what matters.
Navigation and meaning live mostly in rendered HTML. Discovery is duplicated in plain JSON and plain text.
Design rules are embedded in long docs. Design rules are also packaged as a standalone skill.
Tokens are often visible only in code or screenshots. Tokens are directly available as JSON and CSS.

Markdown Support

Markdown is a first-class output here. Reference docs, the skill, and the site index are all published as raw .md files, and the homepage can negotiate to Markdown when an agent requests text/markdown. 

curl https://cf-workers-design-system.adewale-883.workers.dev/site.md

curl https://cf-workers-design-system.adewale-883.workers.dev/ \
  -H "Accept: text/markdown, text/html"

Requests to / that prefer text/markdown are rewritten to the Markdown index and returned with Vary: Accept. Markdown responses also advertise discovery headers and token estimates for agent use.
